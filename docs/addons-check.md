# addons-check.md — Stremio Addon Health Audit

This document is the master checklist for verifying that every built-in
Stremio addon in `py_stremio/components/addons/types/` is wired up
correctly AND that the filter, parser, and download pipeline handle its
stream shape correctly.

It is generated by `scripts/audit_addons.py` and updated whenever a new
addon is added or the filter changes.

---

## 1. Critical bug found during this audit

### `cloudscraper_client._short_url` crashed on `httpx.URL`

**File:** `py_stremio/components/addons/cloudscraper_client.py`
**Symptom:** Every 4xx/5xx response from any addon was reported as
`CloudscraperError: 'URL' object has no attribute 'decode'`, hiding the
real HTTP status code.

**Root cause:** `httpx.Response.url` is an `httpx.URL` object, not a
plain string. `_short_url(resp.url)` called `urllib.parse.urlparse()`,
which calls `.decode()` on each argument during its coercion phase, and
`httpx.URL` has no `.decode()` method.

**Fix applied:** coerce the URL to `str()` up front, both inside
`_short_url` and in the `HTTPError` message construction in
`_raise_for_status`.  The audit now surfaces the real status code
(403/404/429/500/502/503) instead of a misleading Python error.

```python
def _short_url(url: str) -> str:
    url_str = str(url) if url else ""
    parsed = urlparse(url_str)
    ...
```

**Regression risk:** all 382 unit tests still pass.  The fix is local
to error-message construction and has no effect on the happy path.

## 2. How to run the audit

```bash
cd /home/strubloid/apps/py-stremio
python scripts/audit_addons.py
```

The script walks every `HttpAddon` subclass under
`py_stremio/components/addons/types/`, instantiates it, and for each one:

1. Validates that `base_url` is a well-formed `http(s)://` URL.
2. Calls `get_url(api_key=None)` and confirms the result starts with `http(s)://`.
3. GETs `/manifest.json` to confirm the addon is reachable and that
   the response is valid JSON.  This is a cheap liveness probe — a
   working manifest usually means the addon service is up.
4. If the manifest is OK, sends a real `/stream/series/{IMDB}:{S}:{E}.json`
   request for the user-reported case: One Piece S23E3 (IMDB `tt0388629`).
5. Inspects the first returned stream and:
   - confirms it has at least one of `infoHash` / `url`
   - parses it through the real `select_quality_streams` filter
   - records whether the filter accepted or rejected it
6. Classifies the result as `PASS` / `WARN` / `FAIL`.

The current test query lives at the top of `audit_addons.py`.  To audit
against a different show, edit `TEST_SERIES_ID` and `TEST_TITLE` and
re-run.

### Exit codes
- 0 always — the audit is read-only and never modifies anything.
- Look at the report section ("PASS / WARN / FAIL") and the
  per-addon notes.

## 3. The checklist — what to verify per addon

When you add a new addon, or when an existing one stops working, walk
through every item below.

### 3.1 Class definition

- [ ] Class lives in the correct category folder
      (`types/torrentio_family/`, `types/comet_family/`, `types/aggregators/`,
      `types/anime/`, `types/iptv/`, `types/regional/`, `types/misc/`,
      `types/debrid/`).
- [ ] Class inherits from `HttpAddon` (from `py_stremio/components/addons/base.py`).
- [ ] Class has a unique `name` (this is the identifier used for
      blacklisting and config storage).
- [ ] `base_url` is the addon's real public URL with no RD key, no
      `manifest.json` suffix, and no trailing slash.
- [ ] `get_url(api_key=None)` returns just `self.base_url` for simple
      addons.  Only addons that need RD-key injection override this.
- [ ] If the addon needs a per-host URL configurer (Torrentio, Comet,
      HDHub, StremThru, Brazuca, Guindex, Nyaa, Yomi, IntellDebridSearch),
      the configurer is registered in `addon.py` and the class calls
      `configure_addon_url()` from `get_url()`.
- [ ] The class is exported from `builtin_addons.py` and `__init__.py`.
- [ ] The class is listed in `_EXPLICIT_NAMES` in `addon_registry.py` so
      the dynamic factory does not clobber it.

### 3.2 Runtime reachability

Run the audit. For each addon confirm:
- [ ] `manifest.json` returns 200 and parses as JSON.
- [ ] The manifest's `catalogs` list contains at least one catalog
      (catalog metadata is how Stremio discovers content types).
- [ ] `/stream/series/{IMDB}:{S}:{E}.json` returns 200 and a JSON body
      with a `streams` array.
- [ ] The `streams` array is non-empty for at least one realistic
      query.
- [ ] The first stream has either `infoHash` or `url` (without one of
      these the stream cannot be downloaded).
- [ ] The first stream passes `select_quality_streams()` against a
      query that the addon should be able to answer.

### 3.3 Stream shape compatibility

The download pipeline parses each stream into a `StreamInfo` and then
runs it through `_filter_streams_by_target_episode`.  The filter uses
three signals:

- **Title signal** — derived from `name`, `title`, and `filename`
  fields.  The `_has_show_title_signal` helper strips codec/quality
  tokens (e.g. `webrip`, `aac`, `x265`, `torrent`, `4k`, `1080p`)
  and reports whether any remaining show-name-like word is present.
- **Episode signal** — `s<SS>e<EE>` token, season-only `s<SS>` token,
  or `season<SS>episode<EE>` form in the combined text.
- **Finished-release markers** — year (1900-2099) + resolution
  (480p/720p/1080p/2160p/1440p/4320p) + format keyword (bluray,
  web-dl, etc.).  When at least 2 of the 4 marker groups are
  present, the text is treated as a finished release, and the
  episode check is enforced strictly.

An addon stream is **accepted** when at least one of the following
holds:

- it contains a matching S/E token in its text
- it contains a matching season-only token in its text
- it has no S/E token AND no finished-release markers (info-hash
  addons whose text is just a generic label)
- the title check accepts (target show name appears in text, OR text
  has no title signal)

An addon stream is **rejected** when it has BOTH a contradicting
show name AND a contradicting S/E token, or when its IMDB ID
metadata disagrees with the target IMDB.

For each addon, verify that its typical stream shape falls into one
of the accepted categories.  Use the live endpoint to inspect
real responses — the user-reported CIN case showed that the
"info-hash-only" shape is common and the filter must accept it.

### 3.4 Common stream shape issues

| Symptom in stream | Likely cause | Fix |
|-------------------|--------------|-----|
| `name`/`title` are non-empty but contain only quality markers ("4K", "1080p", "WEBRip", "AAC") | info-hash-only addon | Already supported — `_has_show_title_signal` returns False and the episode check is authoritative. |
| `name`/`title` are empty or `None` and the only metadata is in `behaviorHints.filename` | Stream metadata only in filename | Already supported — `filename` is included in `_combined_stream_text`. |
| Show name is only in the URL path (e.g. `cinescrape` style: `name="InfoMedia"`, `url="http://.../One Piece Episode...mp4"`) | URL contains the only show identifier | Not yet supported — consider adding a URL-path check in `_has_show_title_signal` (TODO). |
| Show name uses absolute episode numbers ("One Piece - 1158" instead of "S23E3") | Long-running anime like One Piece, Naruto, Bleach | Currently accepted because there is no contradicting S/E token in the text.  Post-download filename validation is the second line of defense. |
| `title` is a redirect to a non-Stremio debrid login page ("👥 Watch with your friends", "Configure this addon") | Advisory message disguised as a stream | `_is_advisory_stream` catches most cases.  Verify by inspecting the live response. |
| `infoHash` present but `fileIdx` is `0` for a multi-file torrent | Addon always uses file 0 | Treated as `file_idx=0` by default — works for single-file torrents, may be wrong for season packs. |
| All streams from the addon always have `name` set to the addon name and a generic suffix (e.g. "[Castle] 1080p") | Addon returns whatever is on the debrid account, regardless of show | This is the HDHub case — filter correctly rejects wrong-show addons. |

### 3.5 RD-key injection

If the addon supports RealDebrid, verify that:
- [ ] The class overrides `get_url(api_key)` to inject the RD key when
      one is provided.
- [ ] For multi-tenant RD addons (Torrentio, Comet, etc.), the URL
      configurer in `addon.py` handles the pattern.
- [ ] The RD key is **not** stored in the class file or in `addons/addons.txt`.

### 3.6 Blacklisting behaviour

- [ ] When an addon returns a stream that fails the size threshold
      (`MIN_COMPLETED_VIDEO_SIZE_MB`), the addon is added to
      `disabled_servers` for that folder.
- [ ] When an addon returns a stream with a different IMDB ID, the
      addon is added to `disabled_servers`.
- [ ] When an addon returns no streams for a query, the cached
      server list is **not** cleared (only cleared at the end of a
      run when nothing succeeded).

### 3.7 Logging and error reporting

- [ ] Errors are routed through `ErrorReporter` (`report_error()`),
      not `print()` or `logging.error()`.  See `AGENTS.md` for the
      full rule.
- [ ] Sensitive URL params (`apikey`, `token`, `realdebrid`, etc.)
      are redacted in error messages.

## 5. TODOs discovered by this audit

### 5.1 URL-path show-name detection (Cinescrape gap)

**Problem:** Cinescrape returns streams like:
```json
{
  "name": "InfoMedia",
  "title": "1080p BluRay",
  "url": "http://103.225.94.27/Infobase/.../One Piece Episode Of Sabo ... 1080p BluRay.mp4"
}
```

The show name "One Piece" is only in the URL path.  The current
filter looks at `name`/`title`/`filename` but not the URL, so it
incorrectly rejects these streams.

**Proposed fix:** in `_has_show_title_signal`, also consider the
URL path.  Decode percent-encoded chars, lower-case, and check
whether any show-name word appears in the URL path.  This must be
carefully scoped to avoid false positives (URL params often contain
random tokens).

**Risk:** might over-match addons that proxy through generic CDNs.

### 5.2 NoTorrent redirect handling

**Problem:** NoTorrent returns:
```json
{
  "name": null,
  "title": "🌐 1080p - VLC Player (Original Audio)",
  "url": "https://addon.notorrent2.workers.dev/redirect?p=907j8zGScJaJ..."
}
```

The actual show identity is only revealed after the redirect.  The
filter sees a generic label and a redirect URL, so it rejects the
stream.

**Proposed fix:** None.  We cannot resolve redirects during the
filter pass without a real HTTP request per stream (too slow).  The
post-download size check still catches bad redirects, and the
working_addons cache will eventually learn to skip NoTorrent for
queries it cannot answer.

### 5.3 Audit also needs a movie-mode test query

The current audit only tests series queries.  Several addons
(`CineTorrent`, `FENIXFLIX`, `LatinMovies`, `MY CINE`) only serve
movies.  Re-run the audit with `TEST_SERIES_ID = "tt0133093:0:0"`
(The Matrix) to audit movie coverage.

### 5.4 Stream proxy redirect adds ~1s per stream

When the filter passes a stream whose URL is a redirect, the
downloader follows it and the round-trip cost shows up in the
download timeline.  This is not a bug, but it is worth documenting.

## 7. How to update this document

1. After changing the filter in `py_stremio/components/download/stream_download.py`,
   re-run `python scripts/audit_addons.py` and re-check section 3.3.
2. After adding a new addon, walk through section 3 and add a row to
   section 6.
3. After changing `cloudscraper_client.py`, re-run the audit and check
   that the real status codes (not `URL.decode` errors) are surfaced.
4. After changing any URL configurer in `addon.py`, audit the addons
   that use it (Torrentio, Comet, HDHub, StremThru, Brazuca, Guindex,
   Nyaa, Yomi, IntellDebridSearch).
